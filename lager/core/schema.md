# lager/core/schema.php – eigene Tabellen

Legt nur Tabellen mit dem Präfix `lg_` an und fasst Dashboard-Tabellen nie an. Gebaut wird nur, wenn sich diese Datei geändert hat (Marker `lg_meta.schema_build`).

| Tabelle | Inhalt |
|---|---|
| `lg_leiste` | Chaos-Modell (großes Lager): ein Blinker, an eine **Charge** gebunden (`charge_id`). `charge_id` NULL = frei. Code 6-stellig. Dazu `ausloesungen` + `verbrauch_sek` (Nutzung für die Akku-Schätzung) und `batterie_seit`. |
| `lg_platz` | Fulfillment (feste Plätze): Bereich, Regal, Ebene, Fach, Bezeichnung, Blinker (6-stelliger Code), Sender, Notiz. Jede Blinker gibt es nur einmal. |
| `lg_sender` | Sender: Name, Weg (`bruecke`, `direkt`, `cloud`), IP im Lager-Netz, Seriennummer, aktiv. |
| `lg_befehl` | Jeder Leuchtbefehl: Warteschlange für die Brücke und zugleich Protokoll. Status `offen`, `abgeholt`, `ok`, `fehler` oder `verfallen`. |
| `lg_meta` | Einstellungen: Schlüssel der Brücke (`bruecke_token`), letztes Lebenszeichen der Brücke (`bruecke_zuletzt`). |
| `lg_charge_info` | Zusatzinfos je Charge, die es im Dashboard nicht gibt: `aufteilen` (in Kartons splitten), `tracking` (Sendungs-/Paketnummer), `pakete`. |
| `lg_charge_log` | Änderungsprotokoll je Charge: `feld`, `alt`, `neu`, `benutzer_id`/`benutzer_name`, `angelegt`. Gefüllt von `lg_charge_log_add()` (überspringt unveränderte Werte), gelesen von `lg_charge_log_liste($id)`. Zeigt auf der Charge-Seite „wann hat wer was geändert". |
| `lg_versand` | Warenausgang/Sendung: Nummer (WA-…), `kunde_id`, **Empfänger-Snapshot** (`empf_*` inkl. `empf_land` ISO – weltweit), `typ` (paket/palette), `carrier` (manuell/dhl/cargoboard), `status` (geplant/versendet/storniert), `tracking`, `gewicht_kg`, `pakete`, Notiz. Helfer: `lg_versand_anlegen/_kopf_speichern/_status_setzen/_tracking_setzen`, `lg_versand(_liste)`. |
| `lg_versand_pos` | Positionen einer Sendung: `charge_id`/`item_id`, `bezeichnung`+`charge_nr` (Snapshot), `menge`/`einheit`, `abgebucht`; **Zoll (CN23)** `zoll_hs`, `zoll_ursprung` (ISO2), `zoll_wert` (€/Stk), `zoll_gewicht_g`. Helfer: `lg_versand_pos_add/_liste/_del/_abgebucht/_zoll_set`. Bestandsabbuchung beim Versenden läuft über `core/erp.php` (`erp_charge_entnehmen`). `lg_versand` hat zusätzlich `masse_l/b/h` (cm, Fracht) und `dhl_groesse` (gross/klein). |
| `lg_artikel` | **Lager-2-Artikelkatalog** (Stammdaten je Fulfillment-Kunde): `kunde_id`, optional `item_id` (Verkaufsfertig-Item), `typ` (verkaufsprodukt/rohstoff/etikett/beipackzettel/pouchbag/rollenware/karton/sonstiges, `lg_artikel_typen()`), `name`, `verkaufsartikel`, `gewicht_g`, `masse_l/b/h_mm`, `ean`, `kunden_sku`, `mindestbestand`, `produktionszeit_tage` (Override), `etikett_bild` (Datei in data/uploads), `notiz`. Helfer: `lg_artikel_liste/_anlegen/_speichern/_bild_set/_del`, `lg_artikel_typen`. UI: `?p=l2_artikel`. |
| `lg_versand_label` | Vom Carrier (DHL/Cargoboard) erzeugtes Versand-Label je Sendung: `carrier`, `format`, `pdf` (LONGBLOB), `zoll_pdf` (CN23-Zollpapier A4, Nicht-EU), `angelegt`. Helfer `lg_versand_label_set/_label/_hat_label`. Ausgabe über `?p=versand_label` (`&zoll=1` = Zollpapier). |
| `lg_gebinde` | **Eigene Gebinde-/Karton-Aufkleber (Spec 5.6)** für Verpackung ohne Hersteller-Charge: `nummer` (`GB-00001`, eindeutig), `charge_id` (Dashboard-Charge), `wareneingang_ref` (Momentaufnahme), `lieferant_id` (für Regress), `laufnr` (Gebinde X von N), `angelegt`. Helfer: `lg_gebinde_nummer()` (Zähler in `lg_meta['gebinde_zaehler']`), `lg_gebinde_anlegen($charge_id,$anzahl,$lief,$ref)`, `lg_gebinde_liste/_per_nummer/_zahl/_del`. UI: `?p=gebinde` (verwalten + Scan-Auflösung), PDF: `?p=gebinde_etikett`. |
